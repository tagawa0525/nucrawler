# 処理の流れ

`nucrawler crawl` が巡回から和訳までを進める仕組み。

## ステージ

処理はステージ（取得 → 本文抽出 → 要約 → embedding → 採点 → 和訳 → 見出しの和訳 → 同じ報道の判定 →
プロファイルの見直し）ごとに成果物の有無で進み、中断しても次回は続きから再開する。最後に語彙の整理（`tidy`）が動く。

- `crawl --until STAGE` はそのステージまで、`crawl --only STAGE` はそのステージだけを動かす
- `crawl --requests-only` は Web UI から依頼された和訳だけを処理する
- 途中で Ctrl-C（または SIGTERM）で止めても、次回は続きから処理する。2 回目のシグナルで即座に終了する

## LLM のバックエンドとクォータ

- 要約・採点・和訳は Claude Code の headless 実行（`claude -p`）で行い、サブスクリプションの枠内に収める
  （`llm.backend = "copilot-cli"` にすると GitHub Copilot CLI（`copilot`）で行い、AI Credits の枠を使う。
  `llm.score_backend` などで工程ごとに選べ、採点だけ Claude のまま、ほかを Copilot にするといった使い分けもできる）
- 5 時間枠と週次枠の使用率を見て、時間帯ごとの上限を超えないように止まる（`config.toml` の `[quota]`）。
  Copilot では、今月の消費クレジットを月の経過に合わせた上限までに抑える（`[copilot_quota]`）
- `[quota]` の時間帯は `timezone_offset_hours`（既定 JST）で判定する

## 並行とロック

- 取得（fetch・extract）は 1 つずつ動く。1 つの取得の中では、同じホストへは `http.per_host_delay_secs` の間隔を空けて
  順に、ホストどうしは並行してアクセスする
- LLM を呼ぶ処理（要約・採点・和訳・見出しの和訳・同じ報道の判定と `redo`・`profile suggest`・`eval --profile`）は、
  取得ともほかの LLM の処理とも並行して動く（例：長い `redo digest` の最中でも、和訳の依頼や定時の crawl は待たされない）。
  同じ記事・同じモデルを同時に処理しないよう、処理する記事は DB 上で予約してから扱う
- クォータの判定は呼び出しのたびに DB の最新の使用率を読むので、ほかの実行の呼び出しも入る（並行している呼び出しの分だけ、
  上限を少し超えることはある）
- 同時に動くバックエンド（claude・copilot）の数は、実行をまたいで `llm.concurrency` 個まで。1 つの実行の中でも、
  要約・採点・和訳・見出しの和訳・同じ報道の判定はそれぞれ `llm.concurrency` 本まで同時に呼ぶ（応答を待つ間に次を呼ぶので、
  過去分をまとめて処理するときに 5 時間枠を使い切れる）。語彙の整理は 1 つずつ
- 同じロックを別の実行が持っていれば、終了コード 75（EX_TEMPFAIL）で終わる（`crawl` の途中でロックが
  取れなかったときも同じで、それまでに処理した分は残る）。`--wait-lock` を付けると空くのを待ってから続ける（unit はこちらを使う）。
  待っている間に止められたら、そこで終わる

## 失敗と再試行

失敗した記事は 1 時間から倍々の間隔で 5 回まで再試行し（そのステージが対象にする期間にあるうち）、そこで諦める。
諦めた記事は要約や採点が無いまま残るので、`status` に最後に諦めた理由を添える。成功すると失敗の記録は消える。

## 見出しの和訳（`title`）

本文が取れず要約できない英語記事（記事ページがボット対策で開けない IAEA など）は、見出しだけを和訳して
一覧・検索・受付箱に日本語の見出しを出す（`llm.title_batch_size` 件ずつまとめて訳す）。
期間（`backlog_days`）では絞らず、後から本文が取れて要約ができれば要約の見出しを使う。

## embedding（`embed`）

要約は embedding（意味のベクトル）にもする。LLM を使わず、OpenAI 互換の embeddings API を
`config.toml` の `[embedding]` で呼ぶ。設定が無ければ何もしない。モデルを替えたら `nucrawler embed rebuild` で作り直す。

プロファイルの関心分野と推薦しない話題も embedding にし、その近さで全員の記事に点数を付ける（関心分野は重み付きの最大、
推薦しない話題は減点。直近の記事の中での百分位にする）。今は `eval` で LLM の採点と比べるためだけに使い、一覧などは
LLM の点数のまま（計画 010）。

## 同じ報道のグループ（`story`）

同じ出来事を別のソースが報じた記事は、同じ報道のグループにまとめる。

- 候補：日本語の見出しと要約の文字の類似度で選ぶ。日付の差は ±21 日まで。英語の記事も要約で比べるので、言語をまたいでまとまる
- 判定：候補のある記事だけ、LLM が同じ出来事の報道（same）か、続報など同じ案件の別の出来事（related）かを判定する
  （`llm.story_batch_size` 件ずつ）
- グループ：same の組をつないで作る。既存のグループは 1 つの候補として判定させ、大きさは 8 件まで。
  同じ組を両方の向きで判定して割れたら（片方が related や無関係なら）つながない

画面での扱いは [Web UI](web-ui.md#同じ報道のグループ) を参照。

## 版とやり直し

要約と和訳はモデルと訳語集の時点ごとに版を残し、`redo` で別のモデルや新しい訳語集でやり直せる（[CLI](cli.md#redo)）。

## 推薦点

推薦は、関心プロファイル（分野と重み）をもとに LLM が付けた点数に、記事に付けた評価（★1〜5）から学んだ補正を
足した「推薦点」で並べる。補正はトピック・ソース・当たった関心分野と推薦しない話題ごとで、LLM は呼ばない。

- 評価が無ければ推薦点は LLM の点数と同じで（0 点だけは、端を丸めるので 1 点）、評価が増えるほど補正が効く
- 補正の強さは `[recommend] prior_strength`（既定 20、大きいほど LLM の点数に近いまま）。
  既定の強さでは、評価 1 件で特徴を共有する記事が動くのは数点で、同じ傾向の評価が数十件そろうとはっきり効く
- 当たり具合は `eval` で比べられる（[CLI](cli.md#eval)）
- LLM の採点そのものは関心プロファイルだけで決まるので、関心の分野を大きく見直すならプロファイルを直す
  （下の `review` ステージが評価から案を作る。CLI の `profile suggest` でも作れる）

## プロファイルの見直し（`review`）

評価を推薦に効かせるもう 1 つの経路として、プロファイルそのものを評価から直す（計画 016）。

- 前の案（無ければ今のプロファイルの版）の後に評価が 10 件以上増えた利用者について、評価を根拠に LLM が更新案を作る
  （`profile suggest` と同じプロンプト。モデルは採点と同じ）
- 今のプロファイルと案で、評価したすべての記事を採点し（採点済みの記事では LLM を呼ばない）、一覧と同じ規則で
  選んだ点数の一致率を比べて、案を保存する。案が今と同じなら採点せずに「変えない」と残す
- 利用者の設定が「当てる」（既定）で、案の一致率が今より 0.05 以上高く、★4〜5 と ★1〜2（無ければ ★3 以下）が
  それぞれ 5 件以上あれば、案をそのまま新しい版にする（出どころ「自動で適用」）。当てなかった案は採用か見送りを待つ
- 案は根拠にした評価で測るので甘く出る。当てた版が使われていた間の一致率は履歴で見られ、前の版に戻せる
  （[Web UI](web-ui.md#興味プロファイル)・[CLI](cli.md#profile-historyprofile-revert)）
- LLM が止まったら（上限・失敗・中断）その利用者の案は保存せずに終え、次の実行で作り直す

## トピックの語彙と訳語集

- トピック：要約では語彙から選び、当てはまる語が無いときだけ LLM が新しい語を 1 個まで提案して語彙に加える。
  LLM が足した語の表記揺れは、crawl の最後の `tidy` ステージで週 1 回（`llm.tidy_interval_days`）LLM に見直させ、
  既存の語へ自動で統合する。編集の仕方は [CLI](cli.md#topics)
- 訳語集：要約と和訳で訳語と略語を揃えるための一覧で、DB が正本（初期値は DB を作るときに入る）。
  1 つの訳語（略語を添えられる）に原語を複数結び付け、表記の揺れや略語をまとめて同じ訳にする。
  LLM には、渡す記事（切り詰めた後の見出しと本文）に原語が出てくる語だけを載せる。
  原語は語の単位で当て（複数形の s / es は当てる）、大文字だけの略語は大文字のときだけ、ほかは大文字小文字を問わない。
  編集は Web UI の ⚙️ → 訳語集（[Web UI](web-ui.md#管理者の画面)）
