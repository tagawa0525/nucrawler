# 利用者の反応を「評価」と「状態」に分ける（1〜5 の評価・消えないカード・閾値の選択）

## 背景

2026-09-29 時点で、推薦の並び順と表示の閾値は LLM の点数（`scores.score`）だけで決まる。反応が推薦に効く経路は
`profile suggest`（LLM が案を作り、人が取り込む）だけで、外部のレビュー（ChatGPT）から「LLM 頼みに過ぎる」と指摘された。
行動から評価を変える仕組み（後述の「この後」）を入れる前に、行動の記録を整理する。

### 今の記録のしかたと問題

- 行動はすべて `events`（kind は open_detail・open_translation・up・down・bookmark・dismiss）に記録し、ブックマークの
  今の状態だけ `bookmarks` に持つ（`event_id` の CASCADE で、取り消した行動のブックマークを外す）。
- **状態（処理した）と評価（関心）が同じ操作に乗っている。**
  - 一覧の左スワイプの「見ない」（dismiss）は評価では負例として数えるが、使う側は「既読・処理済み」の意味でも使っている。
    本番の 10 件のうち 3 件は詳細を開いて読んだ後に見送っていた。開かずに見送ったものも、「関心が無い」と
    「似た記事をもう読んだ」とが区別できない。
  - ブックマーク（後で読む）は、読む前に見出しで選んだもので、読んだ後の評価とは別物なのに正例として数えている。
  - スワイプするとカードが消えるので、振り分けは「一覧を片付ける」操作になり、評価の意味を保てない。
  - 👎 は詳細を開かないと付けられない。評価は 👍/👎 の 2 値だけ。
- **記事ごとの今の判定を 3 か所で別々に導いている。**
  - 一覧で隠す（`src/db/read.rs` の `rows.feedback` / `rows.dismissed`）：最新の 👍/👎 が 👎、または見送りが一度でもある。
  - 確認枠の候補（`src/db/read.rs` の `ItemScope::Explore`）：明示的な反応が一つでもある。
  - 評価のラベル（`src/db/eval.rs` の `labels()`）：最後の明示的な反応。
  - そのため、見送った後に 👍 した記事は eval では正例なのに、一覧からは隠れたままになる。
  - 正例・負例の分け方も `Label::positive`・`label_evidence`・`eval::render` に重複している。
- 本番のデータ（2026-09-29）：👍 4・🔖 4・👎 5・見送り 8 記事、詳細を開いた記事 40。利用者は 1 人。

## 方針

**評価と状態を、別の操作・別のテーブルに分ける。**

| 対象         | 置き場所                                                            | 意味                                             | ラベル       |
| ------------ | ------------------------------------------------------------------- | ------------------------------------------------ | ------------ |
| 評価         | `ratings(user_id, article_id, value 1..5, rated_at)`（1 記事 1 行） | 「この記事を自分に推薦すべきだったか」           | **これだけ** |
| ブックマーク | `bookmarks(user_id, article_id, bookmarked_at)`                     | 後で読む                                         | しない       |
| 既読         | `reads(user_id, article_id, read_at)`                               | 処理済み。開いたときと、カードの操作で付く       | しない       |
| 開いた記録   | `events`（open_detail・open_translation だけ）                      | 行動の記録。後で暗黙のシグナルに使うかもしれない | しない       |

- 評価の段階の意味：5 必読、4 読んでよかった、3 どちらでもない（推薦されても困らないが得もない）、2 不要、
  1 二度と出さないでほしい。画面に書いておく。
- **評価なしと 3 は別物。** 評価なしは行が無いこと（判断していない）で、学習にも評価にも使わない。
  3 は判断した結果で、5 より低く 1 より高いべき記事として使う。値 0 や NULL は持たない。
- 評価したら既読にする（処理済み）。
- 似た記事をもう読んだから要らない、というときは既読だけを付け、1〜2 は関心が無いときに使う。
  同じ出来事の記事が複数のソースから届く重複は、推薦の評価とは別の課題として残す（「この後」）。
- 判定はテーブルを読むだけになるので、導き方の食い違いは構造として無くなる。
- カードは消さず、印を付けるだけにする。一覧から外れるのは次の訪問から。

### 既存のデータの移し方

- 👍/👎：記事ごとに最後の 👍/👎 を、👍 → 4、👎 → 2 で `ratings` に移す（`rated_at` はその行動の時刻）。
- 見送り：既読に移す（`read_at` は最初の見送りの時刻）。ラベルにはしない（誤ったラベルが混ざるより、減るほうが害が小さい）。
- ブックマークの行動：`bookmarks` の状態はそのまま（`bookmarked_at` は付けた行動の時刻）。ラベルにはしない。
- 開いた記録：既読に移す（`read_at` は最初に開いた時刻）。`events` にも残す。

## PR の分け方

各 PR は TDD（RED のテストのコミット → GREEN の実装のコミット → 必要なら REFACTOR）で進める。

### PR 1 `feat/ratings`：評価を 1〜5 にする

- マイグレーション `0025_ratings.sql`：`ratings` を作り、👍/👎 を移し、`events` から up・down の行を消す
  （`events` の CHECK の作り直しは PR 2 でまとめて行う）。
- `db/signals.rs`（新設）：`Rating`（1〜5 の値。`TryFrom<u8>`）、`Db::rate(user, article, Option<Rating>, now)`
  （`None` で評価なしに戻す）。評価は既読も付ける……のは `reads` を作る PR 2 から。
- 一覧・検索・詳細：`ListItem.feedback` を `rating: Option<Rating>` に置き換える。
  - 一覧の既定で隠す条件の「👎」を「評価 1〜2」にする。
  - 検索の `liked=1` を `min_rating=N`（評価 N 以上）にする。一覧上部の 👍 は `/search?min_rating=4`。
    CLI は `--liked` を `--min-rating N` にする。
- 評価（`eval`）・確認枠・`profile suggest` のラベルを `ratings` だけにする（ブックマーク・見送りはラベルでなくなる）。
  - `eval`：AUC を、評価の違う組のうち点数の順が合っている割合（一致率。同点は半分）に広げる。2 値のときは AUC と同じ。
    点数帯ごとの表は、評価 1〜5 ごとの件数にする。
  - 確認枠の内訳：評価 4〜5 を関心、1〜2 を不要、3 を中立として数え、見逃し率は関心 /（評価した記事）。
  - `profile suggest`：根拠に評価の値を渡す（`<reaction rating="4" ...>`）。トピックごとの件数は関心・中立・不要。
- 詳細の画面：👍/👎 を 1〜5 の評価のボタンにする（付けた値をもう一度押すと評価なし）。
  受付は `POST /articles/{id}/rating`（`value=1..5`、空で評価なし）。`/feedback` の up・down は受け付けない。
- 一覧のカード：👍 の印を ★N にする。
- JSON（`/api/*`）と MCP：`feedback` を `rating`（1〜5 か null）にする。
- README を直す。

### PR 2 `feat/reads-and-bookmarks`：既読とブックマークを状態にする

- マイグレーション：`reads` を作って開いた記録と見送りを移す。`bookmarks` を `bookmarked_at` を持つ形に作り直す
  （`event_id` をやめる）。`events` を open_detail・open_translation だけに作り直す。
- `Db::set_read(user, article, bool, now)`、`Db::set_bookmark(user, article, bool, now)`。開いたら既読（既にあれば
  最初の時刻を保つ）。評価したら既読。
- 一覧の区切り：前の訪問より前の欄は、今回の訪問の区切りより**前に**既読になった記事を隠す（今回の訪問で既読に
  した記事は、再読み込みしても残る）。評価 1〜2 を隠す条件は SQL（一覧の既定）に残す。フィード・JSON・MCP も
  一覧の既定と同じ記事を返すので、訪問の区切りを持たないそれらでも不要の記事を隠すため。
- ブックマークした記事も一覧に残す（今は一覧から外している）。
- 確認枠の候補は、既読・評価済みの記事を除く。返すのは評価の無い記事。
- 受付：`POST /articles/{id}/read`・`POST /articles/{id}/bookmark`（`on=1|0`）。`/feedback` と `/feedback/undo` はやめる。
- 一覧のスワイプは、右でブックマーク・左で既読の印を付ける受付に向け直す（カードが消えるのは PR 3 で直す）。

### PR 3 `feat/card-marks`：一覧のカードで評価・印を付ける

- カードの下に「☆☆☆☆☆ 🔖 ✓」を並べ、どれも付け外しでき、カードはその場に残る（取り消しのトーストは不要になる）。
- 右スワイプで 🔖、左スワイプで既読を切り替える。キーボードは j/k で移動、1〜5 で評価、0 で評価なし、l で 🔖、h で既読。
- JavaScript が無くても、フォームの送信（戻り先は同じページ）で同じことができる。
- 詳細の画面も同じ部品を使う。

### PR 4 `feat/score-threshold`：閾値を選べるようにする

- 一覧上部の ⭐ を数字のボタンにし、0〜90 の 10 刻み（と設定の `web.min_score`）から選ぶ。値は `?min=N` で持ち、
  既定は `web.min_score`。`?all=1` は `?min=0` に置き換える。
- 0 は「すべて」：未採点・軽水炉と無関係・評価 1〜2 の記事も出す。
- 確認枠は見逃し率を偏りなく測るためのものなので、選ぶ基準は設定の `web.min_score` のまま。
  一覧に既に出ている記事は確認枠に重ねて出さない。

## この後（別の計画にする）

- **行動から点数を補正する**：LLM の点数はそのまま残し、Rust の中で最終点を出す。関心の度合いを、LLM 点と
  トピック・ソース・当たった関心分野ごとの補正の和で表し、補正は評価の数が少ないほど 0 に縮める。理由（「★4 以上 3/4：
  トピック X で +8」）を見せる。`eval` は同じデータで学習と評価をしないよう、1 件ずつ外して比べる（leave-one-out）。
  一覧の点数と閾値は最終点に切り替え、確認枠も最終点で選ぶ。
- 暗黙のシグナル（和訳の依頼・コメント・開いた記録・ブックマーク）は、eval で効くと確かめてから弱いラベルとして足す。
- 同じ出来事の記事の重複をまとめる。
