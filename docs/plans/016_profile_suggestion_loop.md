# 星の評価からプロファイルを直し続ける（更新案の自動化と履歴）

この計画は、何をなぜ決めたかを残す。競合や端のケースの扱いは、各 PR でテストとともに決める。

## 背景

推薦の点数は、関心プロファイル（関心分野・重み・補足、推薦しない話題）と記事だけで決まる。星の評価（★1〜5、計画 003）を
推薦に効かせる経路は、評価から学ぶ補正（計画 004）と、プロファイルの見直しの 2 つで、後者は今は CLI の手作業である。

```sh
nucrawler profile suggest --out new.toml   # 評価を根拠に LLM が更新案を作る（docs/plans/profile-suggest.md）
nucrawler eval --profile new.toml          # 今のプロファイルと一致率を比べる
nucrawler profile import new.toml          # 採るなら取り込む
```

2026-10-04 に r995 の評価 43 件（★4 8・★3 12・★2 23）で測ると、今のプロファイルは LLM・embedding ともに一致率
（評価の高い記事ほど点数が高い組の割合。0.5 が当て推量）が 0.44 で、評価とほぼ無関係だった。外れた記事を見ると、
プロファイルで最も重い「規制・審査」（重み 1.0）に当たる審査や工程のニュースが ★2 で、★4 は燃料の材料・濃縮・
設備トラブルの原因と対策・出力向上といった技術寄りの記事だった。`profile suggest` の案（規制・審査を下げ、出力向上・
設備トラブル・サプライチェーンを足す）では一致率が LLM 0.64、embedding 0.53 に上がった（案を作った評価と同じ評価で
測ったので甘めの値）。

仕組みはあるのに、手順が CLI の 3 段で、評価が溜まっても誰も回さないので、プロファイルは最初に書いたまま好みから
ずれていく。利用者の要望は次のとおり。

- 星の評価から、プロファイルが自動で直っていく（既定）。自動で当てるかは利用者が設定で選べる
- 今すぐ直したいときは、Web から案を作れる
- 直した後の推薦が前より悪いと感じたら、前の版に戻せる

## 決めたこと

### プロファイルの版を残し、どの版にも戻せる

- プロファイルを保存するたびに、版（中身・hash・出どころ・理由・保存した時刻）を追記する。消さない、書き換えない
  - 出どころ：`import`（CLI）、`suggest`（案を人が採用）、`auto`（案を自動で適用）、`revert`（前の版に戻す）
- 今のプロファイルは、最新の版と同じ中身を `profiles` に持つ（読む側は今のまま変えない）
- 戻すのは「その版の中身を新しい版として保存する」こと。履歴は一方向に伸びるだけなので、戻したことも履歴に残り、
  戻した後にさらに戻すこともできる
- 戻すと hash が前の版と同じになる。LLM の点数は hash ごとに残っている（古い hash の点数を消さない）ので、
  採点し直さずに前の推薦が戻る。embedding の点数は保存のたびに作り直すが、ベクトルの計算だけで済む

### 版の良し悪しは、その版が使われていた間の評価で示す

「前の方が良かった」を判断する材料として、版ごとに、**その版が今のプロファイルだった間に付けた評価**での一致率と件数を
履歴に並べる。

- 案を作るときの比較（下記）は、案を作った評価と同じ評価で測るので甘く出る。その版の案の根拠にした記事を除けば、
  使われていた間の評価はその版が知らない評価になる。版には根拠にした記事を記録し、この集計から除く
- 評価は付け直すと値と時刻を上書きする（`ratings` は記事ごとに 1 行）。付け直した評価は付け直した時点の版に数える。
  利用者がその時点の推薦を見て付けた評価なので、その版の評価として扱うのが自然である
- 版の一致率は、その版が今でなくなった時点で集計して版に保存し、以後は変えない。後から評価を付け直したり、
  embedding の点数が新しい hash で作り直されたり（古い hash の embedding の点数は消える）しても、過去の版の値は
  動かない。今の版の値はその場で集計する
- 件数が少ない版は値が揺れるので、件数を必ず並べる

### 点数は一覧と同じ規則で選ぶ

> 2026-10-04：一覧の点数を embedding に一本化し、見直しの比較も LLM ではなく embedding でその場で計算する（[計画 017](017_embedding_ranking.md)）。

案の比較・自動で当てる判定・版の一致率は、どれも**その利用者の一覧が記事の順位に使う点数**で測る。`eval` のように
採点器・モデル・プロンプトの版ごとに一致率を出すと、どれを選ぶかで判定が変わり、一覧の順位と違う指標で当てることに
なるためである。点数を選ぶ SQL は、計画 010 の段階 3 で 1 つの断片にまとめる予定のものを使う（段階 3 より先に
この計画を実装するなら、ここでまとめる）。

### 案は、手動でも自動でも同じ手順で作り、同じ手順で比べる

1. 評価を根拠に LLM が案を作る（今の `profile suggest` と同じプロンプト・同じ根拠の集め方）
2. 今のプロファイルと案を、同じ評価に対して採点し、一覧と同じ規則で選んだ点数の一致率を比べる
   （採点は今の `eval --profile` と同じ。LLM なら評価 20 件ごとに 1 回呼ぶ）
3. 案・根拠・根拠にした記事・差分・両方の一致率を保存する

作るきっかけは 3 つ。

- **自動**：`crawl` に、前の案の後に評価が 10 件以上増えた利用者について案を作るステージを足す。毎回のクロールで
  回しても、評価が増えなければ何もしない
- **手動（Web）**：設定画面の「今すぐ案を作る」。LLM を Web のプロセスから呼ばない今の作りに合わせ、依頼を記録して
  訳の依頼と同じ `crawl --requests-only`（15 分ごと）で作る。画面には作成中と出す
- **手動（CLI）**：今の `profile suggest --out FILE` は残す（ファイルに書くだけで、DB の案には入れない）

### 自動で当てるかは利用者の設定（既定は当てる）

- 設定が「当てる」で、案が次を満たせば、案を新しい版として保存する（出どころ `auto`）。手動で作った案も同じ規則で
  当てる（「今すぐ直す」はこの意味）
  - 案の一致率が今より 0.05 以上高い
  - 評価に ★4〜5 と ★1〜2（無ければ ★3 以下）がそれぞれ 5 件以上ある
- 満たさない案や、設定が「当てない」ときの案は、設定画面に未決の案として出し、人が「採用」か「見送り」を選ぶ。
  条件を満たさない案でも、人は採用できる
- 自動で当てても、履歴からいつでも戻せる。既定を「当てる」にできるのはこのため
- 新しい案ができたら、前の未決の案は置き換える（古い評価で作った案を残しても判断を迷わせるだけ）

条件の値（0.05・5 件・10 件）はコードの定数にし、履歴の「使われていた間の一致率」を見て直す。

### Web の設定画面にまとめる

設定画面に「興味プロファイル」の節を足し、次を並べる。

- 今のプロファイル（読むだけ。編集は計画 010 の段階 4 で別に作る）
- 「案を自動で当てる」の切り替え
- 「今すぐ案を作る」と、作成中の表示
- 未決の案：差分（Rust で計算したもの）、LLM の根拠、今と案の一致率と件数、「採用」「見送り」
- 履歴：版ごとの時刻・出どころ・差分の要約・使われていた間の一致率と件数、「この版に戻す」

### 対象の利用者

プロファイルを持つ利用者すべてを対象にする（今は所有者だけがプロファイルを持つ。計画 010 の段階 4 で所有者以外も
持つようになれば、そのまま対象になる）。設定は利用者ごとに持つ。

### 採らなかったもの

- **案を作る評価と比べる評価を分ける**（時系列で分けるなど）：評価が数十件のうちは、分けるとどちらも少なすぎて
  比べられない。甘さは「使われていた間の一致率」と履歴からの戻しで補う
- **LLM を使わずに重みだけを評価から動かす**：★4 の記事が既存の分野に当たらない（出力向上・設備トラブルなど）ことが
  今のずれの主因で、分野を足すには文章を作る必要がある
- **Web のプロセスから LLM を呼んで即座に案を出す**：Web のプロセスは LLM の設定・枠・作業の予約を持たない。
  15 分待ちで足りる

## 変更

PR を分けて順に入れる。テストはそれぞれの PR で決める。

1. プロファイルの版と戻し
   - 版の表（中身・出どころ・根拠にした記事・今でなくなった時点の一致率と件数）を足し、今のプロファイルを保存する経路
     （`profile import` など）をすべて版の追記に通す。今のプロファイルを最初の版として入れる
   - 点数を一覧と同じ規則で選ぶ SQL の断片（計画 010 の段階 3 が未実装なら、ここでまとめる）
   - CLI に `profile history`・`profile revert VERSION`
   - Web の設定画面に履歴と「この版に戻す」、版ごとの使われていた間の一致率
2. 案の保存と自動のステージ
   - 案の表（案・根拠・一致率・状態・きっかけ）と、利用者の設定「案を自動で当てる」（既定は当てる）
   - 案を作って比べる処理を 1 つにまとめ、`crawl` のステージ（評価が 10 件以上増えたとき）から呼ぶ
3. Web の操作
   - 設定画面の「興味プロファイル」の節：切り替え、「今すぐ案を作る」（`--requests-only` で処理）、未決の案の採用・見送り
