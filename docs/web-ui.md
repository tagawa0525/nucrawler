# Web UI

`nucrawler serve` で動く、スマホから読むための画面。

## ログイン

ログイン ID とパスワードでログインする（利用者は管理者が `nucrawler user` で発行する。[CLI](cli.md#user)）。
ログインしていなければ、画面はログイン画面へ移り（ログイン後に元の画面へ戻る）、JSON と書き込みは 401 になる。
セッションは 30 日で、⚙️ の設定画面からログアウトできる。

- パスワードは設定画面で変えられる（新しいパスワードは 12 文字以上 1024 バイト以下）。変えると、ほかの端末のログインと
  フィードの URL は使えなくなる（Cookie や URL を写し取られていても、変えれば締め出せるように）。今のパスワードの誤りは
  ログインの失敗と同じく数え、待ち時間に入るとログイン中のセッションもすべて切れる
- HTTP で待ち受けるので、パスワードとセッションの Cookie はネットワークに平文で流れる。社内 LAN や Tailscale など、
  信頼できるネットワークのアドレスで待ち受ける。いつもの URL 以外（見知らぬ名前やアドレス）ではログインしない
- ログインに続けて失敗すると待たされる（ID ごとに 6 回目から 1・2・4・8 分、10 回目以降 15 分。接続元の IP ごとに 21 回目から 15 分）。
  失敗の表示は、ID が無い・パスワードが違う・待ち時間中のどれでも同じ
- 書き込み（GET 以外）は、ブラウザの Origin がこのサーバーでなければ 403

## 上部のバー

一覧の上部のバーには、🔍・最低点の選択・評価の選択・👁・🔖・⚙️ を並べる（見出しや説明は出さない）。カードの下の印と同じ並び。
🔍 は検索（検索のフォームはここからだけ出る）。管理の画面へは右端の ⚙️（`/settings`）から入る。

- 最低点の選択は 00（絞らない）〜90（10 刻み。桁をそろえて 1 桁は 0 を付ける）、評価の選択は「★」（絞らない）・「★1〜2 を隠す」
  （関心が無いと評価した記事を隠し、未評価は残す。一覧の既定）・★1〜★5（評価した記事。最低点と同じく小さい順。★4 は ★4 以上）・
  「☆」（評価の無い記事だけ）。関心プロファイルの無い利用者の一覧では、最低点の選択の先頭に「--」（最低点なし）が加わり、
  これが既定になる（採点が無いので、点数で絞ると何も出ないため）
- どちらの選択も「絞らない」は、閉じた選択では 00・★ と書き、開いた一覧では「-」と書く。「★1〜2 を隠す」は、閉じた選択では
  ★3+☆ と書く。絞っているあいだは緑になる。評価の選択は ★ と黄色の枠で最低点と見分ける
- 👁（既読）と 🔖（ブックマーク）は押すたびに、絞らない（白）→ 印のある記事だけ（緑。既読だけ・ブックマーク中だけ）→
  印の無い記事だけ（赤と斜線。未読だけ・ブックマークなしだけ）と切り替わる。名前（読み上げ・ツールチップ）に今の状態と押したときの次の状態を出す

画面ごとのバーの意味：

- 一覧の画面（`/`）：最低点は `?min=N`（設定の `web.min_score` は 10 刻みでなくても選択肢に加わる。00 は `?min=0` で、未採点・
  軽水炉と無関係の記事も出す。「--」は `?min` なしで、プロファイルの無い利用者の既定）、評価は `?rating=hide-low`・`?rating=N`（☆ は
  `?rating=0`、絞らないは `?rating=any`）、👁 は `?read=1`・`?read=0`・`?read=any`（絞らない）、
  🔖 は `?bookmarked=1`・`?bookmarked=0`
- 検索の画面（`/search`）：先頭は 🔍 の代わりに 🏠（一覧へ戻る）。バーは検索の条件で、最低点は `min_score`、評価は `min_rating`
  （☆ は `unrated=1`、★1〜2 を隠すは `hide_low=1`。既定は絞らない）、👁 は `read=1`・`read=0`（既定は絞らない）、
  🔖 は `bookmarked=1`・`bookmarked=0`。変えるとほかの条件はそのままに検索し直す
  （検索のフォームにはこれらの欄を置かない。設定の最低点は選択肢に加えない）
- 詳細の画面：先頭は 🏠。バーは一覧の既定の表示を指す

## 一覧

一覧は「前回の訪問の後に届いた記事」と「それより前の記事」に分かれ、推薦点の高い順に並ぶ（プロファイルが無ければ採点が無いので、新しい順）。
👁 が既定の未読だけなら、既読の記事はどちらの欄にも出ない（後の欄の見出しは「過去の未読」。絞らないなら「過去の記事」、既読だけなら「過去の既読」）。

### 推薦点

表示する最低点・確認枠の閾値・検索の最低点も推薦点（[処理の流れ](pipeline.md#推薦点)）で判定する。
推薦点が LLM の点数と違うときは、点数に触れると「LLM 72・補正 +9」のように LLM の点数と補正を出す。
詳細には補正の内訳（例：「推薦点 81（LLM 72）：関心分野 燃料 +6、ソース WNN +3」）を出す。

### 絞り込みの既定と全期間の絞り込み

- 選んだ最低点未満の記事は出ず、未採点・軽水炉と無関係の記事は最低点を 0 にしたとき（`?min=0`）だけ出る。
  ただし最低点なし（プロファイルの無い利用者の既定）では推薦点で絞らないので、未採点の記事も出る（軽水炉と無関係は隠す）
- 評価 1〜2 の記事は、評価の選択が既定の「★1〜2 を隠す」のあいだは出ない（最低点とは関係しない）
- 既読の記事は 👁 を絞らない・既読だけにしたときだけ出る
- 評価した記事（★1〜★5・☆）か 🔖（ブックマーク中だけ）で絞り込むと、一覧の期間によらず全期間から新しい順に出す
  （両方を選ぶと両方に当たる記事）。見出しに「ブックマーク中・★4 以上（全期間）」のように、何で絞ったかと全期間であることを出す。
  評価を「★」か「★1〜2 を隠す」に戻し 🔖 をブックマーク中だけから外すと一覧に戻る（ブックマークなしだけは一覧の中で絞る）
- 最低点・👁・評価の既定は、一覧では設定の最低点（プロファイルが無ければ最低点なし）・未読だけ・★1〜2 を隠す、絞り込みでは
  00・絞らない・絞らない（集めた記事を見返すため）。
  一覧と絞り込みを行き来すると、行き先の既定に戻る。絞り込みの中では引き継ぐ

### 条件で隠れている記事

- 条件で隠れている記事があれば、一覧の後に「条件で隠れている記事：点数 50 未満・未採点 32 件・既読 12 件・★1〜2 3 件」のように、
  条件ごとの件数（その条件だけを外したときに加わる記事の数）を、その条件を外した表示へのリンクにして出す
- 1 件も出ないときは「新しい記事はありません」の代わりに「点数 50 以上・未読だけ・★1〜2 を隠す に合う記事はありません」と、
  効いている条件を出す

### カードの印と操作

- カードの下には、点数・評価の星（☆☆☆☆☆）・👁（既読）・🔖（ブックマーク）が並び、印は押すとその場で付け外しできる
  （ページは移らない）。点数は未採点なら数字の無い青い印になる。🔖・👁 は上部の切り替えと同じく、付いていれば緑、外れていれば白
- 左右のスワイプでも印を切り替えられる。右でブックマーク（後で読む）、左で既読
- キーボードでは j / k（↓ / ↑）で記事を選び、1〜5 で評価、0 で評価なし、l（→）でブックマーク、h（←）で既読を切り替える。
  どれも押し直せば元に戻る
- カードの印を付け外しして 👁・🔖・評価の条件から外れると、カードはその場で隠れ、6 秒ほど「元に戻す」が出る
  （u キーでも戻せる。絞り込みでは件数も合わせる）
- ブックマークした記事は一覧上部の 🔖（`/search?bookmarked=1`）でも読める

### 確認枠

最低点が 0 でなく、プロファイルがあれば、一覧の下に「確認枠」として、設定の閾値（`web.min_score`）未満の記事から毎日 `web.explore_per_day` 件（既定 2）を
無作為に選んで出す。表示されない記事に関心があったか（見逃し）を評価で確かめるため。

- 同じ日は同じ記事を出し、1 つの記事は 1 回しか選ばない
- 評価した記事は枠から消える（候補は未評価・未読の記事）
- 最低点を下げて一覧に出ている記事は、確認枠には重ねて出さない

### 同じ報道のグループ

同じ報道のグループ（[処理の流れ](pipeline.md#同じ報道のグループstory)）は、一覧と確認枠では 1 件にまとめる。

- 代表：推薦点が最も高い記事。カードには「他 2 件（WNN・IAEA）」のように、ほかの記事の数とソースを添える
- 既読はグループ単位で扱う：どれかを読めばグループごと既読になる。読み終えた話を別のソースが後から報じても、一覧に戻ってこない。
  カードの 👁 もグループの状態を出し、既読を外すとグループの記事すべての既読が外れる。検索・全期間の絞り込みでも、
  既読はグループ単位で絞る
- 評価はカードに出る記事（推薦点の最も高い記事）自身の評価で判定する：グループのほかの記事に ★1〜2 があっても、
  カードの記事が ★3 以上か未評価なら出る。カードの記事を ★1〜2 にすると、その話はほかの記事に入れ替わらずに隠れる
- 検索ではまとめない
- 詳細には「同じ報道」（グループのほかの記事）と「関連記事」（続報など同じ案件の別の出来事。グループなら 1 件にまとめる）を出す

## 評価と既読

- 評価は ★1〜5 で、一覧のカードと詳細で付けられる。「この記事を自分に推薦すべきだったか」を、5 必読、4 読んでよかった、
  3 どちらでもない、2 不要、1 二度と出さないでほしい、で付ける。付けた星をもう一度押すと評価なしに戻る
  （評価なしは判断していないことで、3 とは別に扱う）。似た記事をもう読んだだけなら、評価は付けない
- 評価は推薦点の補正の学習と、`nucrawler eval` で当たり具合を測る正解に使う。ブックマーク・既読の印は使わない
- 既読は、詳細か和訳を開いたとき、一覧で既読の印を付けたときに付く。評価（★）は既読とは別の印で、評価しても既読にはならない
- 詳細・全文和訳・原文を開いたことは、開いた記録として残す（後で推薦を見直すときの材料）。
  原文へは詳細の「原文」のリンク（`/articles/{id}/source`）が、開いたことを記録してから元の記事へ移す（原文を開いても既読は変えない）

## 詳細

- 一覧のカードと同じく、点数・評価・👁・🔖 の順に並び、付け外しできる
- 要約の版を切り替えられる。英語の記事は全文和訳を読むか、まだ無ければ依頼できる
- 末尾の「コメントを書く」を開くと、記事に個人的なコメントを何件でも付けられる。
  「公開する」をチェックしたコメントはほかの利用者にも見せ、チェックしなければ（既定）書いた本人だけが見る（🔒 非公開）。
  自分のコメントは「編集」を開いて直したり消したりできる
- 末尾の「訳語の指摘」を開くと、気になった訳を送れる（希望する訳・原語・メモは任意。要約か和訳があるときだけ）。
  「その他の指摘」では種類（和訳の誤り・要約の誤り・トピック・本文の取得漏れ・その他）を選んで内容を送れる。
  指摘は 1 つの記事に何件でも送れ、送った指摘とその対応状況は同じ欄の上に小さく並ぶ
- 取得に失敗しているソースや、LLM の失敗（認証切れなど）は画面の上部に出る

## 検索

検索（`/search`、一覧上部の 🔍）では、一覧で隠す記事や期間外の記事も探せる。条件はすべて AND で、
既定は新しい順（点数順も選べる）。件数の上限は `web.list_limit`。
結果のカードでは、ソース・日付の横に、評価した記事は ★ と評価（例：★4）、ブックマークした記事は 🔖 が付く。

- `q`：原題・本文・要約・和訳に含む語（全文検索）。空白で区切るとすべてを含む記事に絞る。
  3 文字以上の語は索引で、2 文字以下の語は全文を順に調べて探す
- `since` / `until`：日本時間の年・年月・年月日（`2026` / `2026-09` / `2026-09-20`、`until` はその日・月・年を含む）。
  画面では文字で入れるほか、横の 📅 のカレンダーで日付を選べる
- `topic`：最新の要約に付いているトピック（繰り返すとすべてが付いている記事）。統合した語の別名でもよい
- `source`：ソース（繰り返すとどれかのソース）
- `lang`（`en` / `ja`）、`translated=1`（和訳あり）、`min_rating`（この評価以上。1〜5）、`read=1`・`read=0`（既読だけ・未読だけ。`unread=1` は `read=0` と同じ）、`bookmarked=1`・`bookmarked=0`（ブックマーク中だけ・していない記事だけ）、`unrated=1`（評価なし）、`hide_low=1`（★1〜2 を隠す。`min_rating`・`unrated=1`・`hide_low=1` は 1 つだけ指定できる）、`min_score`（最低点。未採点は除く。0 は一覧の 00 と同じく絞らない）
- `sort`：`newest`（既定）か `score`

## 興味プロファイル

設定画面の「興味プロファイル」（`/settings/profile`）に、今のプロファイル（関心分野・重み・補足と推薦しない話題）と、
版の履歴を新しい順に出す。プロファイルは保存するたびに版として残る（計画 016）。版ごとに、出どころ（取り込み・案を採用・
自動で適用・前の版に戻した）、1 つ前の版からの変更、その版が使われていた間に付けた評価の件数と一致率を出す。
一致率は一覧と同じ規則で選んだ点数で測り、案の根拠にした記事は除き、版が今でなくなった時点の値で固まる。

「更新案」には、評価から作ったプロファイルの案を出す（作り方は [処理の流れ](pipeline.md#プロファイルの見直しreview)）。

- 「案の一致率が十分に高ければ、自動で当てる」（既定はオン）：オフにすると、案はすべて採用か見送りを待つ
- 「今すぐ案を作る」：評価の件数によらず、次の `crawl --requests-only`（15 分ごと）で案を作る。作るまでは作成中と出す。
  評価が 1 件も無ければ作らずに取り下げる。自動で当てるかは、評価が増えて作った案と同じ規則で決める
- 待っている案：今のプロファイルとの違い、LLM が挙げた根拠、今と案の一致率（案の値は案の根拠にした評価で測るので
  甘めに出る）を出し、「採用する」（出どころ「案を採用」の版になる）か「見送る」を選ぶ。新しい案ができると、
  待っている前の案は置き換わる
- 待っている案が無ければ、前回の見直しの時刻と結果（当てた・見送った・変える根拠なし など）を出す

今でない版には「この版に戻す」を出す。戻すと、その版の中身が新しい版として今のプロファイルになり、その版の LLM の
採点がそのまま使われる（CLI の `profile revert` と同じ）。

## 管理者の画面

管理者（所有者）だけができること：訳語集の編集と受付箱（閲覧と対応）。ほかの利用者には 403 で、画面にも編集・対応のフォームや
受付箱への入口を出さない。訳語集は全員の和訳に効く共有のデータで、和訳は所有者の LLM の枠で作るため。
指摘は全員が出せ、一般の利用者が見られる指摘は自分が出したもの（詳細の画面で対応状況と返事を確かめる）だけ。
運用の警告（取得の失敗など。取得した URL やバックエンドの診断を含む）も、管理者の画面にだけ出す。

- 訳語集（`/glossary`）では、訳語ごとに畳んだ項目を開いて訳語・略語・原語（1 行に 1 つ）・メモを直せる（管理者だけ。ほかの利用者にはメモを出す）。
  訳語・略語・原語がほかの訳語と重なると、どの訳語と重なったかを返して保存しない。
  訳語か原語を変えた時刻を残す（初期値の語は持たない）
- 受付箱（⚙️ → 受付箱、`/reports`）には指摘が新しい順に並ぶ（既定は受付中だけ。状況ごとの件数と種類で絞れる）。
  各指摘の「対応」を開いて、状況、結び付ける訳語（訳語の指摘だけ）、ひとことを保存する。
  訳語の指摘の状況は受付中・追加済・登録済・却下で、追加済は訳語集に反映した、登録済は訳語集にあったのに
  その訳が使われていなかった、却下は今の訳のままでよいの意味。ほかの種類は受付中・対応済・却下。
  受付日時と、状況を変えた対応日時を残す（ひとことや訳語だけを直しても変わらず、受付中に戻すと消える）

## フィードと JSON

同じサーバーで、既定の一覧と同じ記事（既読の記事は除く）をフィードと JSON でも出す。
これらを読んでも、開いたことや訪問としては記録しない。

- `/feed.xml?token=…`：Atom フィード（新しい順。和訳タイトル・要約・詳細ページと原文へのリンク）。
  フィードリーダーはログインできないので、利用者ごとのトークンを付けた URL で読む。URL は設定画面で作り、
  作り直すと古い URL は使えなくなる（URL を知っていれば誰でも読めるので、人に渡さない）。
  エントリの ID は元記事の URL から作り、アクセスしたアドレスによらないので、
  別の名前（Tailscale の IP と MagicDNS 名など）で購読しても既読の記事は新着にならない
- `/api/articles`：記事の一覧（一覧と同じく `?min=N` で最低点（`?min=0` で点数で絞らない）、`?rating=` で評価の条件
  （既定は `hide-low`。★1〜2 の記事も受け取るには `?rating=any`）を選べる）。`score` は推薦点、
  `llm_score` は補正の前の LLM の点数
- `/api/articles/{id}`：記事 1 件（最新の要約と、あれば最新の全文和訳）
- `/api/search`：検索画面と同じ条件の検索（一覧と同じ形）。条件の誤りは 400
- `/api/marks?ids=1,2,3`：記事ごとの評価・ブックマーク・既読（最大 500 件）。戻るボタンで一覧に戻ったとき、
  ブラウザが残していた古い一覧のカードの印を、今の状態に合わせるために使う
